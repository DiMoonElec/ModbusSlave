# Подтверждённые проблемы кодогенератора

Дата аудита: 27 октября 2026 года. Проверен весь инструмент, включая код,
существовавший до добавления вычисляемых смещений и `planar_blocks`.
Все перечисленные проблемы открыты; этот файл фиксирует результаты
аудита, а не выполненные исправления. Воспроизведение проводилось на
временных файлах.

Приоритеты: **высокий** — возможна потеря исходных данных или генерация
опасного вызова; **средний** — неверный результат, отказ генерации или
долгая обработка ошибочного ввода; **низкий** — дефект документации.

## 1. Выходные файлы могут затереть YAML или друг друга

**Приоритет: высокий.**

Места: [paths.py](modbus_regmodel/paths.py), `resolve_output_paths()`;
[cli.py](modbus_regmodel/cli.py), цикл записи результатов в `run()`.

Если исходный файл называется `model.yaml`, такой output заменяет его
сгенерированной документацией:

```yaml
output:
  docs: model.yaml
```

При одинаковых путях header и source C-файл перезаписывает заголовок:

```yaml
output:
  header: map.c
  source: map.c
```

В обоих случаях генератор возвращает успешный результат. Проверка путей
не обнаруживает совпадений.

Предлагаемое исправление: до начала записи проверить, что разрешённые
выходные пути различаются между собой и не совпадают с исходным YAML.
Сравнение должно учитывать правила ОС, в частности регистр путей в Windows.

Проверки исправления: оба примера должны завершаться понятной ошибкой
без изменения исходного YAML и существующих выходных файлов.

## 2. Недостаточная проверка имён C-функций и регистров

**Приоритет: высокий для нулевого указателя функции; средний для ошибок компиляции.**

Места: [model.py](modbus_regmodel/model.py), `validate_common()` и
`is_valid_name()`; подстановка значений в [codegen.py](modbus_regmodel/codegen.py).

Getter/setter проверяются только на тип строки. Например:

```yaml
registers:
  - addr: 1
    type: uint16
    getter: "0"
    setter: "0"
```

Описание проходит валидацию. Генератор выводит:

```c
read_reg16_u16(context, 0);
write_reg16_u16(context, 0);
```

MSVC принимает этот C-код даже при проверке с предупреждениями как ошибками:
0 допустим как нулевой указатель на функцию. При обработке обращения
обёртка попытается вызвать этот указатель. На устройстве пример не выполнялся.

Строка `getter: get-value` также проходит валидацию, но приводит к неверному
C-коду. Имена регистров проверяются регулярным выражением с `match()` и
якорем `$`, который допускает завершающий перевод строки: `name: "X\n"`
принимается и разрывает сгенерированный `#define`.

Предлагаемое исправление: проверять полное совпадение имени регистра с
разрешённым форматом; getter/setter должны быть допустимыми C-идентификаторами.
Семантику явно пустых getter/setter следует определить при исправлении,
так как сейчас пустые строки считаются отсутствующими обработчиками.

Проверки исправления: строки `"0"`, `get-value` и имена с переводами строк
должны отвергаться до генерации файлов; обычные имена функций с нижним
регистром и подчёркиваниями должны приниматься.

## 3. Ошибки структуры YAML могут молча исключать обработчики и регистры

**Приоритет: средний.**

Место: [model.py](modbus_regmodel/model.py), загрузка YAML, определение
наличия разделов и `validate_common()`.

Подтверждены три случая с разными причинами.

### Опечатка в имени поля

```yaml
registers:
  - addr: 1
    type: uint16
    geter: get_value
```

Неизвестный ключ игнорируется. Поле становится RESERVED, getter не
вызывается, генерация завершается успешно.

### Неверный тип раздела

```yaml
registers:
  - addr: 1
    type: uint16
blocks:
  name: LOST
  start_addr: 100
  repeat: 1
  registers:
    - type: uint16
      getter: get_value
```

`blocks` задан словарём вместо списка. При наличии корректного `registers`
он полностью игнорируется. Аналогичная проверка типа для `planar_blocks`
уже есть, но для `registers` и `blocks` она несимметрична.

### Повторяющиеся ключи YAML

```yaml
registers:
  - addr: 1
    type: uint16
    getter: get_a
registers:
  - addr: 2
    type: uint16
    getter: get_b
```

`yaml.safe_load()` оставляет последний раздел. В модель попадает только
адрес 2, ошибок нет. Последующие проверки уже не видят потерянные данные.

Предлагаемое исправление: проверять допустимые ключи и типы присутствующих
разделов; при загрузке YAML отвергать повторяющиеся ключи mapping.
Для этого не требуется новая зависимость или универсальный слой схем.

Проверки исправления: все три примера должны завершаться ошибкой без
перезаписи результатов. Намеренный регистр без getter/setter остаётся
допустимым резервом.

## 4. Имя подключаемого заголовка не учитывает output.header

**Приоритет: средний.**

Место: [codegen.py](modbus_regmodel/codegen.py), `generate_source()`.

При настройке:

```yaml
output:
  header: my_map.h
```

генератор создаёт `my_map.h`, но C-файл по-прежнему содержит:

```c
#include "modbus_reg_model.h"
```

Генерация успешна, однако C подключает другое имя: сборка может не найти
заголовок либо найти старый файл с этим именем.

Предлагаемое исправление: согласовать путь include с реальным выходным
заголовком. Учесть размещение `.h` и `.c` в разных каталогах.

Проверки исправления: сгенерировать и скомпилировать модель с нестандартным
именем заголовка, в том числе с раздельными каталогами исходника и заголовка.

## 5. Заведомо неверный массив разворачивается до проверки всего диапазона

**Приоритет: средний.**

Место: [model.py](modbus_regmodel/model.py), `expand_flat()` для регистров
верхнего уровня.

```yaml
registers:
  - addr: 65536
    type: uint16
    count: 3000
```

Этот пример создаёт 3000 ошибок адреса вместо немедленного отказа.
Цикл проходит по всему count, даже если начальный адрес уже за пределами
Modbus. Очень большой ошибочный count соответственно увеличивает время
обработки и объём сообщений; для диапазона, начинающегося с допустимого
адреса, сначала также создаются плоские записи.

Предлагаемое исправление: до развёртки проверить весь диапазон
`addr .. addr + count * size(type) - 1`. Для блоков полная область уже
проверяется до развёртки экземпляров.

Проверки исправления: неверный начальный адрес и переполнение конца массива
должны отвергаться до прохода по элементам; максимальный допустимый массив
должен приниматься.

## 6. Неверный тип output вызывает исключение Python

**Приоритет: средний.**

Место: [paths.py](modbus_regmodel/paths.py), `resolve_output_paths()`.

```yaml
output: output.c
```

Вместо понятного сообщения об ошибке возникает
`AttributeError: 'str' object has no attribute 'get'`. Аналогичная проблема
есть для других непустых значений, не являющихся словарём. Некоторые пустые
значения скрываются выражением `output_cfg or {}`.

Предлагаемое исправление: явно проверить тип output до обращения к его
полям. Определить допустимость null отдельно от пустого словаря.

Проверки исправления: строки, списки, числа и логические значения должны
давать согласованную диагностику; отсутствие output должно сохранять
пути по умолчанию.

## 7. Многострочное описание разрывает таблицу Markdown

**Приоритет: низкий.**

Место: [docgen.py](modbus_regmodel/docgen.py), `_md_escape()` и формирование
строк таблиц.

```yaml
registers:
  - addr: 1
    type: uint16
    description: |
      Первая строка.
      Вторая строка.
```

В описании сохраняются переводы строк. Они попадают внутрь строки таблицы
и разрывают её. Сейчас экранируется только символ `|`.

Предлагаемое исправление: преобразовывать переводы строк в подходящее
представление для ячейки Markdown, например `<br>` или пробелы.

Проверки исправления: многострочный текст и текст с `|` должны сохранять
корректное число строк и ячеек таблицы во всех видах описаний регистров.

## Что проверено при аудите

- Все 76 штатных тестов прошли без пропусков под MSVC, включая выполнение
  запросов через сгенерированный обработчик и настоящий PDU-парсер библиотеки.
- Дополнительно проверена компиляция восьми типов в пяти контекстах:
  одиночный регистр, массив, блок, массив внутри блока и planar.
  С учётом чтения и записи — 80 сочетаний. Использован настоящий заголовок
  API ModbusSlave. Ошибок компиляции не обнаружено.
- Все перечисленные проблемы входного формата и выходных путей
  воспроизведены отдельно; штатные тесты их пока не покрывают.
- Ошибок расчёта адресов и пересечений обычных и planar-блоков при аудите
  не обнаружено. Проверка GCC и проверка на МК в этот аудит не входили.

Обращение со второго слова 32-битного значения — отдельная согласованная
отложенная задача расширения API библиотеки. Она описана в
[разделе 7 спецификации](yaml-descr.md#7-отложенная-задача-обращение-ко-второму-слову-32-битного-значения)
и не считается регрессией текущих изменений.
