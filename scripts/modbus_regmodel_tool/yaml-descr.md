# Спецификация YAML-модели регистров Modbus

## 1. Структура верхнего уровня
Файл должен содержать хотя бы один из разделов: `registers`, `blocks` или `planar_blocks`.
```yaml
includes: ["header1.h", "header2.h"] # Опционально. C-заголовки для генерации.
output:                              # Опционально. Пути для генерации.
  header: "path/to/model.h"
  source: "path/to/model.c"
  docs: "path/to/docs.md"
registers: [...]                     # Список обычных регистров.
blocks: [...]                        # Список повторяющихся групп (блоков).
planar_blocks: [...]                 # Блоки с раскладкой по полям (колонкам).
```

## 2. Типы данных и размер в регистрах
Modbus-регистр = 16 бит. 64-битные типы не поддерживаются. Порядок байт/слов определяется C-библиотекой.
| Canonical | Aliases | Размер (рег.) | Примечание |
| :--- | :--- | :---: | :--- |
| `bool` | `boolean` | 1 | `0` = false, `!=0` = true. |
| `uint8_t` | `uint8`, `uchar`, `byte` | 1 | |
| `int8_t` | `int8`, `char`, `sbyte` | 1 | |
| `uint16_t` | `uint16`, `ushort` | 1 | |
| `int16_t` | `int16`, `short` | 1 | |
| `uint32_t` | `uint32`, `uint` | 2 | Занимает `addr` и `addr+1`. |
| `int32_t` | `int32`, `int` | 2 | Занимает `addr` и `addr+1`. |
| `float` | - | 2 | Занимает `addr` и `addr+1`. |

## 3. Сущности и поля
### Обычный регистр
*   **`addr`** (обяз.): Адрес (hex `0x...` или dec). Диапазон `0x0000..0xFFFF`.
*   **`type`** (обяз.): Тип из таблицы выше.
*   **`name`** (опц.): Символьное имя. Regex: `^[A-Z0-9_]+$`.
*   **`count`** (опц.): Положительное целое число *элементов* (не регистров!). Без `count` один элемент. Занимаемый объем = `count * size(type)`. Даже `count: 1` включает индекс в прототип getter/setter.
*   **`getter` / `setter`** (опц.): Имена C-функций. Определяют доступ: только getter (RO), только setter (WO), оба (RW), ни одного (Reserved/пустышка).
*   **`description`**, **`unit`** (опц.): Для генерации документации.

### Блок (Повторяющаяся группа)
*   **`name`** (обяз.): Имя блока.
*   **`start_addr`** (обяз.): Адрес первого экземпляра.
*   **`repeat`** (обяз.): Кол-во экземпляров блока.
*   **`step`** (опц.): Шаг (в регистрах) между началами экземпляров. По умолчанию равен сумме размеров всех полей: `sum((count или 1) * size(type))`. Явный шаг должен быть положительным целым числом и не меньше этой суммы. Разница — неявный резерв в конце каждого экземпляра.
*   **`registers`** (обяз.): Список регистров внутри блока.

### Регистр внутри блока
Аналогичен обычному регистру, но адрес не задаётся: смещение вычисляется как сумма `(count или 1) * size(type)` всех предыдущих полей в списке `registers`. Порядок полей определяет раскладку. Поле `offset` удалено из YAML-формата; его наличие вызывает ошибку.

### Резервирование и пустые адреса
Резерв — обычный регистр без getter и setter. `type` обязателен, `count` задаёт число элементов этого типа. Для резерва длиной N Modbus-регистров удобно использовать `type: uint16`, `count: N`.

Имя резерва необязательно. Если оно указано, действуют обычные правила уникальности; для нескольких резервов можно использовать `RESERVED_1`, `RESERVED_2`. Слово `RESERVED` не является специальным ключевым словом. Резервы остаются в модели и документации, но для них не генерируются `#define` и `case`.

Вся область блока `start_addr .. start_addr + repeat * step - 1` занята им, включая хвост последнего экземпляра. Другие регистры и блоки не могут размещаться в этой области.

Генератор создаёт `case` только для имеющихся getter/setter. Необработанное чтение библиотека заполняет нулём; необработанную запись игнорирует. Это относится к резервам, хвостам блоков и адресам вне модели. Запись в RO также молча игнорируется, чтение WO возвращает ноль. Отсутствие адреса в модели само по себе не вызывает exception 02; проверки корректности и границ самого Modbus-запроса остаются в библиотеке.

### Planar-блок (`planar_blocks`)

Параметры: `name`, `start_addr`, `repeat`, необязательный `capacity`, непустой список `registers`. Сначала располагаются все экземпляры первого поля, затем все экземпляры второго поля и так далее. Порядок `registers` определяет порядок колонок.

`repeat` задаёт число реально существующих экземпляров. `capacity` — вместимость каждой колонки в экземплярах, по умолчанию равная `repeat`. Значение должно быть положительным целым числом, не меньше `repeat`; `bool` не допускается. `step` в planar-блоке запрещён, даже при наличии `capacity`. В обычных `blocks` параметр `capacity` запрещён: там используется `step` в Modbus-регистрах.

Поля регистра те же, что в `blocks`, кроме **запрещённого `count`**: любое его присутствие, даже `count: 1` или `count: null`, является ошибкой. `offset` также запрещён. `type` обязателен и для резервов; `name` необязателен.

Размер колонки — `capacity * size(type)` Modbus-регистров. Колонка 32-битного поля занимает вдвое больше адресов, чем колонка 16-битного. Смещение колонки вычисляется как `capacity * sum(size(type) предыдущих полей)`. Адрес экземпляра поля: `start_addr + column_offset + instance * size(type)`, где `0 <= instance < repeat`. Выравнивание абсолютного адреса по двум не требуется.

Область блока: `start_addr .. start_addr + capacity * sum(size(type) всех полей) - 1`. Она включает все резервные элементы, в том числе хвост последней колонки. В каждой колонке первые `repeat` элементов соответствуют существующим экземплярам, остальные `capacity - repeat` — резерв. Поле без getter/setter резервирует целую колонку своего типа. Для пропуска нескольких колонок нужно описать несколько таких полей с уникальными именами либо без имён. Чтение резервов даёт ноль, запись игнорируется. Обработчики создаются только для существующих экземпляров.

Изменение размера типа сдвигает последующие колонки. Добавление поля в конец или изменение `repeat` в пределах `capacity` сохраняет адреса существующих полей.

Имена блоков должны быть уникальны среди всех `blocks` и `planar_blocks`. Итоговые имена адресов planar имеют вид `<BLOCK>_<FIELD>_<INSTANCE>`; обычные блоки сохраняют `<BLOCK>_<INSTANCE>_<FIELD>`. Имена проверяются вместе с именами обычных регистров и резервов. Для резервов `#define` и `case` не выводятся.

Все вычисления адресов выполняются в Python при развёртке в плоскую модель. Сгенерированный C использует обычные `switch-case` с конкретными адресами и постоянными индексами экземпляров. Прототипы getter/setter соответствуют регистру в блоке без `count`. Обработка 32-битных значений остаётся прежней (см. раздел 7).

При смене `blocks` на `planar_blocks` вместо `step` задаётся `capacity`. Единицы различаются: `step` — Modbus-регистры, `capacity` — экземпляры. Смена раскладки обычно меняет адреса, а `count` в planar недоступен.

## 4. Логика адресации и прототипы C-функций
**Адресация:**
*   Обычный: `addr + elem_index * size(type)`
*   Блок: `start_addr + instance * step + computed_offset + elem_index * size(type)`, где `computed_offset` вычисляется по предыдущим полям.
*   Planar-блок: `start_addr + column_offset + instance * size(type)`, где `column_offset = capacity * sum(size(type) предыдущих полей)`.

Раскладка разворачивается в Python в плоский список; C-обработчики используют обычный `switch-case` с конкретными адресами.

**Прототипы (T = canonical type):**
| Контекст | Getter | Setter |
| :--- | :--- | :--- |
| Одиночный регистр | `T getter(void);` | `void setter(T value);` |
| Регистр + `count` | `T getter(uint16_t index);` | `void setter(uint16_t index, T value);` |
| Регистр в блоке | `T getter(uint16_t instance);` | `void setter(uint16_t instance, T value);` |
| Регистр в planar-блоке | `T getter(uint16_t instance);` | `void setter(uint16_t instance, T value);` |
| Регистр в блоке + `count`| `T getter(uint16_t inst, uint16_t idx);`| `void setter(uint16_t inst, uint16_t idx, T val);`|

## 5. Строгие правила валидации
1.  **Пересечения:** Запрещено перекрытие диапазонов одиночных регистров с учётом `count` и размера типа и полных областей блоков, включая неявные резервы.
2.  **Границы:** Максимальный занимаемый адрес (включая хвост последнего экземпляра блока) не должен превышать `0xFFFF`.
3.  **Пустота:** Файл без `registers`, `blocks` и `planar_blocks` невалиден.
4.  **Уникальность:** Проверяются итоговые имена адресов: `REG_<NAME>[_<INDEX>]` для верхнего уровня и `<BLOCK>_<INSTANCE>_<NAME>[_<INDEX>]` для блока. Правило применяется и к резервам, хотя их макросы не выводятся. Поле с одним именем в разных экземплярах блока допустимо.
5.  **Planar:** При проверке пересечений и максимального адреса planar-блок занимает всю область `capacity * sum(size(type) всех полей)`, включая хвосты и пустые колонки. Его имена адресов имеют вид `<BLOCK>_<NAME>_<INSTANCE>`. Имена блоков уникальны среди обеих раскладок.

## 6. Минимальные примеры

**Пример 1: Простые регистры и output**
```yaml
output:
  header: "inc/modbus_map.h"
  source: "src/modbus_map.c"
  docs: "docs/modbus.md"
includes: ["device_api.h"]
registers:
  - addr: 0x0001
    name: STATUS
    type: uint16
    getter: get_status
  - addr: 0x0002
    type: bool          # name опущен
    getter: get_en
    setter: set_en
  - addr: 0x0010
    name: ARRAY
    type: float
    count: 4            # Займет 8 регистров (0x0010..0x0017)
    getter: get_arr
```

**Пример 2: Блоки и резервирование**
```yaml
registers:
  - addr: 0x0050
    name: RESERVED
    type: uint16
    count: 10           # Зарезервировано (нет getter/setter)
blocks:
  - name: CHANNEL
    start_addr: 0x0100
    repeat: 3
    step: 0x10          # Шаг 16 регистров
    registers:
      - name: TEMP
        type: float     # Займет 2 регистра
        getter: ch_get_temp
      - name: RESERVED_1
        type: uint16
        count: 2        # Смещения 0x02, 0x03
      - name: COEFFS
        type: int16
        count: 3        # Займет 3 регистра (0x04, 0x05, 0x06)
        getter: ch_get_k
        setter: ch_set_k
```

Если удалить `step` в этом примере, он будет вычислен как `2 + 2 + 3 = 7`. При `step: 0x10` смещения 7..15 каждого экземпляра — неявный резерв.

**Пример 3: Колонки параметров устройств**

```yaml
planar_blocks:
  - name: SLAVE_BY_FIELD
    start_addr: 5000
    repeat: 12
    capacity: 24
    registers:
      - name: STATE
        type: uint16
        getter: get_state
        description: "Состояние устройства"
      - name: COUNTER
        type: uint32
        getter: get_counter
        setter: set_counter
      - name: RESERVED_1
        type: uint16
      - name: ADVANCE_X10
        type: int16
        unit: "0.1°"
        getter: get_advance
        setter: set_advance
```

STATE занимает 5000..5011, хвост колонки — 5012..5023. COUNTER занимает 5024..5047: экземпляр 0 — 5024..5025, экземпляр 11 — 5046..5047; резерв под ещё 12 экземпляров — 5048..5071. Резервная колонка занимает 5072..5095 целиком. ADVANCE_X10 занимает 5096..5107, его хвост — 5108..5119. Полная область блока — 5000..5119. Если удалить `capacity`, она будет равна `repeat`, то есть 12; область станет 5000..5059 без резервных экземпляров в активных колонках.

## 7. Отложенная задача: обращение ко второму слову 32-битного значения

Текущее поведение сохранено: если запрос начинается со второго слова 32-битного значения, отдельного `case` нет, поэтому чтение возвращает ноль, запись игнорируется. Если имеющийся обработчик 32-битного значения получает только одно слово с начала значения, библиотека сообщает ошибку недостаточной длины.

В дальнейшем нужно расширить API ModbusSlave для сообщения ошибки обращения и добавить соответствующие `case` для вторых слов. В текущие изменения это не входит.
